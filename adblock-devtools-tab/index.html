DevTools Adblock Tab

Sends requests that Brave's default filter lists block, allow, or stub, so each one shows a different state in the Adblock tab of DevTools > Network.

  1. Turn on Debug mode in brave://adblock-internals and restart the browser. Without it, the tab can't show which rule matched.
  2. Open DevTools, go to the Network tab, then click Send requests.
  3. Click each request and open its Adblock tab.

RequestRuleAdblock tab shows
https://test-website-b.pages.dev/fetch-later/beacon/stats /beacon/stats (EasyPrivacy) Blocked, with the matched filter and its list.
https://c.statcounter.com/robots.txt ||statcounter.com^$third-party and the exception @@||c.statcounter.com^$image,xhr Allowed by exception, with both the matched filter and the matched exception.
https://www.google-analytics.com/analytics.js .google-analytics.com/ (EasyPrivacy), with the stub from ||google-analytics.com/analytics.js$script,xhr,redirect=google-analytics_analytics.js:5 Blocked, replaced with a stub resource, with .google-analytics.com/ as the matched filter.
https://pcoptimizedsettings.com/wp-content/plugins/koko-analytics/assets/dist/js/script.js ||pcoptimizedsettings.com/wp-content/plugins/koko-analytics/$important,redirect=noop.js,script Blocked, replaced with a stub resource ($important rule).
/styles.css on this site None No adblock rule blocked or allowed this request.

Each request with adblock info also shows a Blocking mode row: Standard, or Aggressive if this site's Shields use aggressive blocking. With Debug mode off, the first request shows a note to turn it on instead of the matched filter.
